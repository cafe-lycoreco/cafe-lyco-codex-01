# ローカル運用ガイド

## 最初に読むもの

このフォルダーをローカルプロジェクトとして開き、`AGENTS.md` と `README.md` を読む。
`.local/INDEX.md` があれば、対象案件の記録を選んで作業を続ける。

## 保存する場所

| 場所 | 用途 | GitHubへの扱い |
| --- | --- | --- |
| `projects/` | 公開可能なコードや資料 | 内容を確認し、明示的に追加 |
| `shared/` | 公開可能な索引・ひな形 | 内容を確認し、明示的に追加 |
| `.local/` | 個人的な引き継ぎ・調査記録 | Git対象外 |
| `.codex/` | このMacのローカル設定 | Git対象外 |
| インポートした個人資料 | 保全用の原本 | `.gitignore` で除外を確認 |

`.gitignore` は誤追加を減らす仕組み。暗号化・バックアップ・公開可否の自動判定ではない。
一度追跡されたファイルは除外ルールだけでは追跡から外れない。公開前に必ず差分を確認する。

## 作業の順番

1. `git status --short --branch` で作業ブランチと未保存の変更を確認する。
2. 公開可能な成果物は `projects/<案件名>/`、私的な記録は `.local/` に保存する。
3. 区切りで必要な引き継ぎを更新する。次のチャットは同じフォルダーの索引から再開する。
4. Gitで履歴に残す場合は対象ファイルを指定して追加し、差分を確認してcommitする。
5. GitHubへ送る依頼がある場合にpushする。ブランチを共有先へ取り込む操作も別途必要になる。

```sh
git status --short --branch
git diff --check
git diff --stat
git ls-files
```

別のMacやCloudは、このMacの `.local/` を自動では読めない。
私的な記録を別環境へ移す場合は、公開リポジトリ以外の保存先を選び、送る内容と範囲を決める。

## Gitの用語

- ブランチ：変更を分けて進める作業の枝。
- commit：ローカルに作る変更履歴。Gitの名前・メールアドレス設定が必要。
- push：ローカルの履歴をGitHubへ送る操作。認証と権限が必要。
- fetch：GitHubの履歴を読み取る操作。ローカル変更を送信しない。

この土台は資料とファイルを管理するプロジェクトで、実行するアプリはまだない。
アプリを作る際に必要なランタイムと依存関係を、その案件の中に追加する。

## 土台を検証する

Python 3.9以降とGitを使用する。追加のPythonパッケージは不要。

```sh
python3 scripts/check_workspace.py
# makeがある場合は同じ検証を以下で実行できる
make check
```

必須ファイル、既知の私的なパスの追跡、除外ルール、空白エラーを確認する。
ファイル本文の秘密情報を自動で完全検出する仕組みではないので、公開前の内容確認も必要。
保全資料のMANIFEST.jsonを検証する場合は `--manifest <パス>` を指定する。

## この初期セットアップのGit運用

- GitHubの既定ブランチを共有元として確認し、作業は `codex/` で始まる別ブランチで進める。
- ローカルの `main` とGitHubの既定ブランチ名は、必ずしも同じではない。
- 作者情報はこのリポジトリだけに設定する。公開用コミットにはGitHubの非公開用メールアドレスを使う。
- プラグインのGitHub接続と、ターミナルのHTTPS/SSH認証は別々に確認する。
- 追加したプラグインが存在することと、現在のチャットで実際に呼べる機能があることは区別する。
